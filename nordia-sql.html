Pourquoi 8,4 % de croissance ont coûté 1,3 point de marge

NORDIA Distribution, distributeur B2B de matériel électrique · 10 tables, 27 436 lignes de commande · données fictives

La question

NORDIA Distribution vend du matériel électrique à 420 clients professionnels. En 2025, son chiffre d'affaires progresse de 8,4 %, mais le taux de marge perd 1,3 point et le budget n'est pas tenu. La direction voulait comprendre pourquoi, et savoir où agir.

J'ai répondu avec 32 requêtes SQL sur la base de l'entreprise, puis une note d'une page au comité de direction. Le jeu de données est fictif, construit pour l'exercice.

Q32Le tableau de bord mensuel du comité

Le comité veut chaque mois le réel, le budget, la marge et l'activité commerciale sur une seule ligne.

Le taux de marge réel est sous le budget tous les mois, de 0,5 à 1,3 point : le problème de marge est structurel. Côté technique, deux CTE (réel et budget), une jointure qui part du budget pour garder les douze mois, et une fenêtre nommée pour les cumuls.

Voir la requête Q32
SQL
-- Q32. Tableau de bord mensuel 2025 du comité de direction, en une requête.
WITH reel AS (
    SELECT mois,
           SUM(ca_net_ht)              AS ca,
           SUM(marge_brute_ht)         AS marge,
           COUNT(DISTINCT commande_id) AS nb_commandes,
           COUNT(DISTINCT client_id)   AS clients_actifs
    FROM   v_ventes
    WHERE  statut = 'Livrée' AND annee = 2025
    GROUP  BY mois
),
budget AS (
    SELECT mois,
           SUM(ca_budget_ht)    AS ca,
           SUM(marge_budget_ht) AS marge
    FROM   budget_commercial
    WHERE  annee = 2025
    GROUP  BY mois
)
SELECT b.mois,
       ROUND(r.ca)                                    AS ca_reel,
       ROUND(b.ca)                                    AS ca_budget,
       ROUND(100 * r.ca / b.ca, 1)                    AS atteinte_pct,
       ROUND(r.marge)                                 AS marge_reelle,
       ROUND(100 * r.marge / r.ca, 1)                 AS taux_marge_reel_pct,
       ROUND(100 * b.marge / b.ca, 1)                 AS taux_marge_budget_pct,
       r.nb_commandes,
       ROUND(r.ca / r.nb_commandes)                   AS panier_moyen,
       r.clients_actifs,
       ROUND(SUM(r.ca) OVER cumul)                    AS ca_cumule,
       ROUND(100 * SUM(r.ca) OVER cumul
                 / SUM(b.ca) OVER cumul, 1)           AS atteinte_cumulee_pct
FROM   budget b
LEFT   JOIN reel r ON r.mois = b.mois
WINDOW cumul AS (ORDER BY b.mois ROWS UNBOUNDED PRECEDING)
ORDER  BY b.mois;

Q20Décomposer l'écart de marge

Savoir si une région manque son budget de marge parce qu'elle vend moins (effet activité) ou parce qu'elle vend moins cher (effet prix/mix).

Total : −565 417 €, soit −299 430 € d'effet activité et −265 986 € d'effet prix/mix. La dernière colonne de la requête recalcule l'écart à partir des deux effets : elle vaut zéro sur chaque ligne.

Voir la requête Q20
SQL
-- Q20. Décomposition de l'écart de marge 2025 par région.
--      Effet activité = (CA réel - CA budget) x taux de marge budgété
--      Effet prix/mix = (taux réel - taux budgété) x CA réel
--      Contrôle       : la somme des deux effets doit redonner l'écart total.
WITH reel AS (
    SELECT region, SUM(ca_net_ht) AS ca, SUM(marge_brute_ht) AS marge
    FROM   v_ventes
    WHERE  statut = 'Livrée' AND annee = 2025
    GROUP  BY region
),
budget AS (
    SELECT region, SUM(ca_budget_ht) AS ca, SUM(marge_budget_ht) AS marge
    FROM   budget_commercial
    WHERE  annee = 2025
    GROUP  BY region
),
base AS (
    SELECT b.region,
           r.ca AS ca_r, b.ca AS ca_b, r.marge AS m_r, b.marge AS m_b
    FROM   budget b
    JOIN   reel r ON r.region = b.region
    UNION ALL
    SELECT 'TOTAL', SUM(r.ca), SUM(b.ca), SUM(r.marge), SUM(b.marge)
    FROM   budget b
    JOIN   reel r ON r.region = b.region
)
SELECT region,
       ROUND(m_b)                                             AS marge_budget,
       ROUND(m_r)                                             AS marge_reelle,
       ROUND(m_r - m_b)                                       AS ecart_total,
       ROUND((ca_r - ca_b) * (m_b / ca_b))                    AS effet_activite,
       ROUND((m_r / ca_r - m_b / ca_b) * ca_r)                AS effet_prix_mix,
       ROUND((ca_r - ca_b) * (m_b / ca_b)
             + (m_r / ca_r - m_b / ca_b) * ca_r
             - (m_r - m_b), 6)                                AS controle_doit_valoir_0
FROM   base
ORDER  BY region = 'TOTAL', ecart_total;

Q23La balance âgée

Mesurer le risque client au 31 décembre : combien reste dû, et depuis combien de temps.

La condition de date se trouve dans le ON du LEFT JOIN, pas dans le WHERE : une facture sans aucun règlement reste dans le résultat, avec un reste dû égal à son montant TTC. Placée dans le WHERE, elle disparaîtrait et l'encours serait sous-estimé.

Voir la requête Q23
SQL
-- Q23. Balance âgée des créances au 31/12/2025.
--      Reste dû = TTC facturé - règlements reçus au plus tard le 31/12/2025.
--      La condition de date est dans le ON du LEFT JOIN : une facture sans
--      règlement reste dans le résultat avec un reste dû égal à son TTC.
WITH reste AS (
    SELECT f.facture_id,
           f.date_echeance,
           f.montant_ttc - COALESCE(SUM(r.montant_regle), 0) AS reste_du
    FROM   factures f
    LEFT   JOIN reglements r
           ON  r.facture_id     = f.facture_id
           AND r.date_reglement <= DATE '2025-12-31'
    WHERE  f.date_facture <= DATE '2025-12-31'
    GROUP  BY f.facture_id
),
tranches AS (
    SELECT reste_du,
           CASE WHEN DATE '2025-12-31' <= date_echeance      THEN '1. Non échu'
                WHEN DATE '2025-12-31' - date_echeance <= 30 THEN '2. Retard 1 à 30 j'
                WHEN DATE '2025-12-31' - date_echeance <= 60 THEN '3. Retard 31 à 60 j'
                WHEN DATE '2025-12-31' - date_echeance <= 90 THEN '4. Retard 61 à 90 j'
                ELSE                                              '5. Retard > 90 j'
           END AS tranche
    FROM   reste
    WHERE  reste_du > 0.005
)
SELECT tranche,
       COUNT(*)                                                   AS nb_factures,
       ROUND(SUM(reste_du))                                       AS encours_ttc,
       ROUND(100 * SUM(reste_du) / SUM(SUM(reste_du)) OVER (), 1) AS part_pct
FROM   tranches
GROUP  BY tranche
ORDER  BY tranche;

Q17Le classement ABC

Savoir sur quelles références concentrer la négociation avec les fournisseurs.

Le LEFT JOIN part de la table produits pour garder les références sans vente (classe C, marge nulle). La part cumulée se calcule avec SUM() OVER (ORDER BY marge DESC ROWS UNBOUNDED PRECEDING).

Voir la requête Q17
SQL
-- Q17. Classement ABC des 180 références sur la marge 2025.
--      LEFT JOIN depuis produits : une référence sans vente reste dans le
--      classement (marge nulle, classe C).
--      A jusqu'à 80 % de la marge cumulée, B jusqu'à 95 %, C au-delà.
WITH marge_ref AS (
    SELECT p.produit_id,
           p.reference,
           p.libelle_produit,
           p.famille,
           COALESCE(SUM(v.marge_brute_ht), 0) AS marge
    FROM   produits p
    LEFT   JOIN v_ventes v
           ON  v.produit_id = p.produit_id
           AND v.statut     = 'Livrée'
           AND v.annee      = 2025
    GROUP  BY p.produit_id, p.reference, p.libelle_produit, p.famille
),
cumul AS (
    SELECT *,
           SUM(marge) OVER (ORDER BY marge DESC, produit_id
                            ROWS UNBOUNDED PRECEDING) / SUM(marge) OVER () AS part_cumulee
    FROM   marge_ref
),
abc AS (
    SELECT *,
           CASE WHEN part_cumulee <= 0.80 THEN 'A'
                WHEN part_cumulee <= 0.95 THEN 'B'
                ELSE 'C'
           END AS classe
    FROM   cumul
)
SELECT reference,
       libelle_produit,
       famille,
       ROUND(marge)                    AS marge_2025,
       ROUND(100 * part_cumulee, 1)    AS part_cumulee_pct,
       classe
FROM   abc
ORDER  BY marge DESC, produit_id;

3Ce que je recommande

La note au comité tient sur une page. Elle se termine sur trois actions, chacune avec un responsable et un ordre de grandeur.

  1. 1

    Encadrer la remise : grille maximale par segment et par famille, validation au-delà, blocage des ventes sous le prix d'achat, et des objectifs commerciaux fixés aussi sur la marge.

    Responsable : direction commercialeGain estimé : 363 k€ de marge par point de remise récupéréDélai : 3 mois

  2. 2

    Relancer à J+5 après l'échéance, bloquer les commandes au-delà du plafond d'encours (121 clients le dépassent), revoir les 268 factures réglées en partie et provisionner les créances à plus de 90 jours.

    Responsable : ADV et comptabilité clientsGain estimé : 1,9 M€ de trésorerie si le DSO revient à 65 joursDélai : 6 mois

  3. 3

    Renégocier les prix d'achat des 38 références de classe A, qui pèsent 77 % des achats.

    Responsable : achatsGain estimé : 184 k€ par point de baisse obtenuDélai : 12 mois

4Points de vigilance

  • Les doublons de clients. Vingt raisons sociales existent sous plusieurs identifiants. Un seul cas est un doublon probable (même ville, même segment) : regroupé, il deviendrait le premier client de l'entreprise. Les autres sont à vérifier par le SIREN avant toute fusion.
  • Le délai contractuel. Je l'ai pondéré par le CA (40,7 jours) pour le comparer à un DSO lui-même calculé sur le CA. La moyenne simple donnerait 40,3 jours.
  • La région. Elle existe à la fois sur la fiche client et sur celle du commercial. J'ai vérifié qu'elles coïncident sur les 7 867 commandes avant de retenir celle du client.
